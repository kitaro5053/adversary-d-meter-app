# 惨劇RoopeR ルール裁定スキル

## 出典・利用について
本スキルは、BakaFire Party さん製作のボードゲーム『惨劇RoopeR』の**非公式**
ファンメイド裁定ツールです。同梱の `rules/` は惨劇RoopeRルールブック・カード
記載の能力等を出典明記のうえ転載しています（BakaFire二次創作ガイドライン
https://bakafire.main.jp/rooper/sr_dl_04_sozai.htm に基づく）。
本スキルに関する質問・不具合などを公式（BakaFire Party）へ問い合わせないで
ください。ご連絡は作者（X @kitaro5053dev）までお願いします。

惨劇RoopeR 5th の **First Steps (FS)** と **Basic Tragedy X (BTX)** のルール質問に、
同梱の知識ベース（`rules/`）と決定的裁定エンジン（`engine/`）だけを根拠に答える。
拡張セットは範囲外＝「原本確認」と答える。捏造禁止、不明は「要確認」と明示する。

## 基本姿勢（厳守）
- 回答は同梱 `rules/` の記述のみを根拠にする。無いことは推測・一般論で補わない。
  未確定なら「知識ベースに未確定です。原本（主人公の書／脚本家の書）で確認してください」と伝える。
- **ネタバレ禁止**：特定脚本の配役・犯人・バッドエンド条件・正解は答えない。一般ルールのみ。
- **FS と BTX の差異**（最後の戦いの有無、ルールXの枚数、登場役職・事件）を意識する。
  どちらのセットか不明なら確認する。
- 『Basic Tragedy X』の X はアルファベット。ギリシャ文字『χ』は別ルール『不定因子χ』＝混同しない。
- 前提自体がルール違反（1/loopカードの複数使用、禁止エリアへの移動、主人公が暗躍カウンター、
  死体に行動カード等）なら、その前提が成立しない旨と根拠を指摘し、誤った前提で計算を続けない。
- 回答の最後に根拠ファイルと見出しを『参照: 60_faq_rulings.md / 〇〇』のように明記する。
- 日本語で、結論 → 理由 → 参照 の順に簡潔に。

## 判定エンジンをいつ・どう使うか（最重要）

**数え上げ・裁定を含む質問では、必ず決定的エンジンを実行し、その出力を確定結論として使う。
自分で数値を再計算してはいけない。** 対象は次の5種類：

- (A) 行動解決フェイズの数え上げ（暗躍/移動＋不安/友好/移動禁止）→ `phase` 省略（既定 action_resolution）
- (B) 脚本家能力フェイズに不安を何個置けるか → `phase = "mastermind_unrest"`
- (C) 脚本家能力フェイズに暗躍を何個置けるか → `phase = "mastermind_anryaku"`
- (D) 事件が発生するか（犯人生存＋不安臨界以上） → `phase = "incident"`
- (E) 友好能力が使えるか／脚本家が拒否できるか → `phase = "goodwill_ability"`
- (F) 今ループが終了するか／敗北判定のタイミング → `phase = "loop_end"`

### 手順
1. 質問を下記スキーマの**盤面JSON**に変換する（あなた自身が抽出器を兼ねる。裁定・推論はしない）。
   語彙は `rules/` に出てくる正式名称を使う（エンジンが未知語を弾く）。
2. JSON をファイル（例 `board.json`）に書き、コード実行ツールで次を走らせる：

   ```bash
   python run_engine.py board.json
   ```

   （このスキル同梱の `run_engine.py`。`engine/` を import して adjudicate→render する）
3. 標準出力の「# エンジン裁定（決定的・確定済み・最優先）」ブロックを**そのまま確定結論**として扱う。
   - 冒頭にエンジンの最終値を明記してから理由を述べる。
   - 自分の推論がエンジンと食い違ったら **エンジンが正**。自分の計算を捨てる。
   - `[エンジン非起動]` が返ったら（スキーマ拒否＝前提が矛盾/創作、または裁定エラー）、
     その理由を踏まえて通常のルール説明にフォールバックする（無理に数値を出さない）。
4. 出力に「⚠ 確認盤面」や感度フラグがある場合、**確定数値は変えず**、
   「未指定カードは無しと仮定した結論」である旨を一言添える。

数え上げに該当しない一般的なルール質問（用語の意味、フェイズ順、勝利条件の概念など）は、
エンジンを使わず `rules/` を根拠に直接答えてよい。

## 盤面JSONスキーマ

```json
{
  "set": "FS" または "BTX",
  "phase": "action_resolution"（既定）/ "mastermind_unrest" / "mastermind_anryaku" / "incident" / "goodwill_ability" / "loop_end",
  "question_target": {"name": "<エリア名/キャラ名/フェイズ名>", "kind": "board" / "character" / "phase"},
  "characters": [{"name": "...", "role": "...", "area": "病院/神社/都市/学校",
                  "alive": true, "forbidden": ["..."], "goodwill": 0, "unrest": 0}],
  "placements": [{"owner": "mastermind" または "p1"/"p2",
                  "card": "暗躍+2"/"暗躍禁止"/"移動←→"/"不安+1"/"友好+2" 等,
                  "target": "<エリア名 or キャラ名>", "target_kind": "board"/"character"}],
  "board_anryaku": {"学校": 0, "神社": 0},
  "rules": ["不穏な噂"],
  "incident": {"culprit": "<犯人キャラ名>", "name": "<事件名(任意)>"},
  "goodwill_ability": {"character": "<行使キャラ名>", "ability": "<能力名(任意)>"},
  "loop_end": {"protagonist_death": false, "loop_end_effect": false,
               "is_final_day_end": false, "defeat_condition_met": null},
  "assumptions": ["補完した仮定を日本語で列挙"]
}
```

### 変換のコツ
- 明示されていない裁量カードは入れない（inert補完）。ただし黒猫の毎ループ暗躍など強制効果は反映してよい。
- 主人公の暗躍禁止が2か所にあるなら別々の主人公＝owner を p1, p2 に分ける（各主人公の手札に1枚ずつ）。
- 同一プレイヤーは1対象に2枚不可。不安を重ねるなら別 owner（例: 脚本家 不安+1 と 主人公 不安+1）。
- `forbidden` は分かる場合のみ。省略すればエンジンがキャラ既定値で補完する（`[]` で禁止を消さない）。
- (B) 不安：関係キャラの role・goodwill・area を必ず書く（「医者がミスリーダーで友好2」→ role=ミスリーダー, goodwill=2）。
- (C) 暗躍：クロマクは role=クロマク・area を書く。「不穏な噂」が脚本にあれば rules に入れる。
- (D) 事件：犯人を incident.culprit と characters の両方に入れ、犯人の unrest（不安数）と alive を必ず書く。
  事件効果（誰が死ぬ等）はJSONに入れない・創作しない（ネタバレ回避）。
- (E) 友好能力：行使キャラの role・goodwill・alive を書き、goodwill_ability.character に名前を入れる。
- (F) ループ終了：characters は不要。loop_end に状況フラグを入れる（主人公死亡=protagonist_death、
  キーパーソン死亡等のループ終了効果=loop_end_effect、最終日のターン終了=is_final_day_end、
  敗北条件が成立しているか=defeat_condition_met）。敗北条件そのものは脚本依存＝ネタバレなので創作せず、
  分からなければ defeat_condition_met は null（要確認）。

## 用語の確定的な意味（エンジン出力の読み方）
- 『暗躍禁止が実効』＝その暗躍+は全て打ち消されて **0**（−1ではない）。
- 『主人公2枚で自滅』＝暗躍禁止が**不発**になり暗躍+はそのまま通る。
- 『カルティストが無視』＝そのボードの暗躍禁止は**不発**。
- 移動の成否・各キャラの最終現在地もエンジンが確定済み。移動先依存の能力は移動が成立した先にのみ働く。
- 不安/友好カウンターは 0 未満にならない（無い不安への −1 は空振り）。
- 事件発生＝犯人生存 かつ 犯人の不安が不安臨界以上。臨界0（黒猫）は不安0でも発生だが効果は「何も起きない」。
- ループ終了：敗北条件の途中成立ではループは中断しない（最終日まで進む）。主人公死亡等のループ終了効果は即終了。
  敗北判定はループ終了時。**数値以外の結論（事件の発生可否・友好能力の可否/拒否・ループ終了と勝敗）も
  エンジンが確定済み**＝自分のフェイズ順推論で上書きしない。
